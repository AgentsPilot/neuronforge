## 1. What must differ between environments

The **current** setup (which Meta app each environment's MA names and WA names belong to, and whether one app serves both; which environment the WhatsApp webhook subscription points at; which Slack app, if any) is recorded in the private inventory by role, checked at use time, and reported by role.

| Setting | Rule per environment |
|---|---|
| Meta app per environment | `META_ADS_CLIENT_ID` and `META_ADS_CLIENT_SECRET` on a target come from **one** recorded app, set together or not at all, and with A1 set. Where one app serves several environments or both name families, every change to it is a change to all of them |
| MA redirect URIs | Each **loaded** Meta plugin's callback, exactly as its definition builds it, at each environment's stable A1 address (`domains.md`). Only a stable address can be registered. A callback for a plugin outside the profile is registered only if recorded |
| Meta app mode and permissions | Production's app is live, not in development mode, and every scope the loaded Meta definitions request is available at the access level the recorded audience needs (vendor terms, confirm at use time). Development mode admits only users with a role on the app |
| WA-W token | Set on the target the recorded webhook subscription points at. Elsewhere unset is safe: the route refuses (MS-4). With no receiving environment recorded, it is expected unset on every target. Never the same value as any other secret |
| WA-W subscription | One recorded receiving environment per Meta app, or none recorded: the callback is the stable A1 address plus the definition's `webhook_config.endpoint_path`, with the fields the definition implies subscribed. One callback per app (vendor fact, confirm at use time) |
| WA-O, SL names | No plugin in the active profile reads them (MS-1). The deprecated V1 strategy also reads the Slack secret name (SL-V1). Whether they stay set is FU-D6g-a's decision |
| SL-V1 names | The two tunnel names never on a deployed target (catalogue: forbidden on production and preview). `NEXT_PUBLIC_SLACK_CLIENT_ID` not set unless recorded |

"Local" is guidance for whoever runs the app locally. DO reads no `.env*` file, so local is never a DO check. A loopback or tunnel redirect is registered only on a non-production app.

## 5. Gotchas

1. **Three plugins are not loaded** (MS-1). A stored connection for one of them cannot run, and its connect answers 404. Never read a Slack, WhatsApp or Meta Ads failure as a credential fault.
2. **Unset is not refused by our code** (MS-2). It surfaces as a vendor error page, or at the token exchange. The placeholder line is logged once per instance load (each cold start), not per request.
3. **The configuration ID is substituted but not sent** (MS-3). Setting it changes nothing at `origin/main`.
4. **One client, two plugins** (MS-5): a secret change touches both Meta plugins, and every environment that shares the app.
5. **No refresh path for Meta** (MS-5): expiry means a reconnect by the owner, not drift.
6. **One unavailable scope fails the whole dialog** (MS-6).
7. **The Graph version is pinned in two places** for each loaded Meta plugin (MS-7), and Meta retires versions on its own schedule (vendor fact).
8. **The verify token is only checked when Meta verifies** (MS-4; that Meta sends it only on "Verify and save" is a vendor fact). A wrong token breaks nothing until the next verification.
9. **One webhook callback per app** (vendor fact, confirm at use time): two environments on one app cannot both receive.
10. **The callback answers one origin** (`google.md` §5 applies to every plugin through the same callback route): a connect started from a per-deployment host completes at Meta, but the page never hears of it.
11. **Development mode admits only role users** (vendor fact): a passing connect by an admin of the app proves nothing about customers.

## 7. Tiers and order against the deploy

**Tiers** (`env-change-protocol`; nothing restated). Production tier (SA reviews the plan, the user executes): on a Meta app production uses, any secret reset, any redirect URI added or removed, any change to the mode, permissions, login configuration, privacy or data-deletion fields, and any change to the webhook callback, its fields or a "Verify and save"; a change to production's verify token; creating a new app for production (it changes the client ID); the same on a Slack app production uses; removing any of these names from production. A change to an app used **only** by non-production environments, as recorded, is reversible: the user applies it after the approval in chat. Where one app serves several environments, every change to it is production tier.

| Change | When |
|---|---|
| Meta app secret reset | Whether Meta keeps existing tokens valid after a reset is a vendor fact, confirm at use time. Until it is confirmed once on a non-production app and recorded, plan it as a cut-over that may force every connection of that app to reconnect: reset → set the secret on every target that shares the app at once → deploy Ready → P-MS-2, P-MS-3, then P-MS-4 if approved. New connects fail until the deploy is Ready |
| Verify token rotation | Set the new token on the receiving target → deploy Ready → P-MS-5 → "Verify and save" with the new token (P-MS-6). Nothing to retire: Meta checks the token only at verification (vendor fact) |
| A new or changed callback path, or a new environment | Its redirect registered on the app for every stable address before merge, or before that environment serves the connect |
| A scope a loaded Meta definition starts to request | Available on the app (and approved where Meta requires) before merge (MS-6) |
| App address moves (`domains.md` §7) | In step 5: add the new redirect URIs; switch the webhook callback only after the new address is Ready and serves the route (one callback per app, vendor fact, confirm at use time, so there is no overlap); then P-MS-6. Remove the old redirect URIs in step 8 |
| A new Meta or Slack app (client ID change) | Every existing connection of the plugins on it must reconnect: an owner-facing change, planned and announced as such |
| A plugin added to the active profile | This file gains its probe rows and its redirects are registered before merge (T-MS-11) |
| Removing WA-O, SL or SL-V1 names | After FU-D6g-a decides |
